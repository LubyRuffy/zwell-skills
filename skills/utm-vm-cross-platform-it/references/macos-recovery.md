# Mac 来宾恢复与验收

## 共享网络失联

先分开记录宿主路由／虚拟接口、来宾网卡 carrier／地址／默认路由、来宾 SSH 服务和受信 SSH 应答。来宾运行且 sshd 在监听、但没有 carrier 或 IP，同时宿主缺少 VM 接口时，继续猜 IP 或反复启动 sshd 无法确认根因。查当前宿主共享网络服务日志。只有当前日志和进程证据支持时，才把失败归因到宿主网络服务。

- **先恢复可用的工作通道。** 共享文件夹执行队列只有在真实映射、目标 VM 身份、当前服务世代和无副作用探针回执都吻合时才可用。检查其是否确实具备命令执行，以及运行进程是否处于目标 GUI 会话。诊断／维护信箱的应答不提供这两项能力。维护锁的回执也不能代替原生 runner 对用例资源的准入和收尾。
- **再独立修复网络。** 保留首个错误和当前网络配置。重启 VM、更新宿主、修改共享模式或防火墙属于独立维护。先按已有授权核对资源所有权、影响与回滚。修复后用目标网卡、路由及固定主机密钥下的新 SSH 应答验收。一次临时变化或服务 PID 更新不能证明网络恢复。

## 控制台与解锁

1. 先查宿主和来宾会话状态。宿主可交互时，绑定真实 UTM 进程、窗口和当前来宾，查看新画面。输入只发往该来宾窗口，并遵守项目对宿主窗口焦点的限制。黑帧时，按已有授权唤醒该来宾的显示，随后重新取帧。黑帧或缺失锁定字段的原因仍可能未知。
2. 当前画面确认为指定 CI 账号的登录页时，有持续授权就用已配置通道自行恢复。准备好接收端再核对新帧，保持进程、窗口、账号和时限匹配，凭据只在内存流转。一次 AX 查找拒绝时，可改用已验证且绑定该窗口的 UTM 键盘路径。已是桌面则直接核验。成功输入或前台激活之后，继续检查新桌面画面和实际回执。
3. 宿主锁屏且无独立已准入通道时，保留待验收状态和下一条可验证的准入条件。不操作宿主锁屏、TCC、口令或其他会话。常规来宾登录在已有授权范围内无需反复确认。

## 队列、验收与收尾

- 复用项目已有私有通道与锁。队列采用短期、单次请求和可核对的 claim／终局。把请求 ID、服务世代及新鲜回执绑定当前目标。等待超时且结果未知时，先检查同一请求的原始响应、进程和资源，禁止重复按键、重复提交或假定没有执行。
- 保留原件并在相同包上验收。检查完整版本／源码／制品 SHA-256、实际原生窗口和受影响操作。原生截图与 AX 可能不是同一瞬间，分别按其实际内容解释。访问恢复、登录和普通 smoke 各有边界。
- 保留首错、stdout／stderr、时间和明确的清理结果。等待自有子进程退出，核对资源所有权后才清理。无法证明清理时暂停该资源上的新用例，可继续其他独立工作。既有有效的同包证据可复用。环境恢复不使旧失败变成通过。

## 持久恢复设施的验收

需要应对宿主或网络长期不可用时，优先复用获准的带外通道。若另行获准建设服务，优先来宾本地的受限服务和专用私有信箱，权限只覆盖所需操作。分别实测冷启动登录前应答、锁屏时允许的操作、无网时执行、超时回执及锁释放。只实测过诊断的服务记录为诊断可用。原生 GUI 能力要另用真实用例验收。
