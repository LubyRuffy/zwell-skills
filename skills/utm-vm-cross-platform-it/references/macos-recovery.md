# Mac 来宾恢复与验收

## 共享网络失联

先分开记录宿主路由／虚拟接口、来宾网卡 carrier／地址／默认路由、来宾 SSH 服务和受信 SSH 应答。来宾运行且 sshd 在监听、但没有 carrier 或 IP，同时宿主缺少 VM 接口时，继续猜 IP 或反复启动 sshd 无法确认根因。查当前宿主共享网络服务日志。只有当前日志和进程证据支持时，才把失败归因到宿主网络服务。

- **先恢复可用的工作通道。** 共享文件夹执行队列只有在真实映射、目标 VM 身份、当前服务世代和无副作用探针回执都吻合时才可用。检查其是否确实具备命令执行，以及运行进程是否处于目标 GUI 会话。诊断／维护信箱的应答不提供这两项能力。维护锁的回执也不能代替原生 runner 对用例资源的准入和收尾。
- **再独立修复网络。** 保留首个错误和当前网络配置。重启 VM、更新宿主、修改共享模式或防火墙属于独立维护。先按已有授权核对资源所有权、影响与回滚。修复后用目标网卡、路由及固定主机密钥下的新 SSH 应答验收。一次临时变化或服务 PID 更新不能证明网络恢复。

## 控制台与解锁

1. **选择当前可用的画面与输入通道。** 有直接控制授权且项目允许时，绑定真实 UTM 进程、窗口和目标来宾。AX 找不到安全输入框时仍可检查该窗口绑定的 UTM 键盘路径。宿主锁屏或无法使用宿主界面时，若来宾已经启用 Screen Sharing、SSH 可达且已有授权，可经固定主机密钥的 SSH 隧道连接来宾的 Screen Sharing 服务。项目的 SSH／共享队列观察入口只证明其实际探测到的能力。两条 GUI 路径均沿用现有服务、TCC 和锁屏策略。
2. **登录以新鲜画面为准。** 黑帧时可按已有授权唤醒目标来宾再取帧。VNC 认证和旧截图仅作通道诊断，缺失的结构化锁标志保留为未知，并遵守具体 helper 的准入要求。画面确认是目标 CI 账号的登录页且接收端已准备好时，在有效期内提交一次既有凭据，随后取得新的目标桌面画面。账号、输入目标或结果不明时，先按同一请求查证。
3. **在同次受控会话内交接。** 登录后保持会话，在实际执行主体中重新验证当前桌面和 Accessibility／录屏权限，再启动 runner。SSH 启动的 helper 被 TCC 拒绝时，可用已有授权且验证过权限的来宾 Terminal 执行同一项目入口，遵守既有锁和交接回执。临时隧道和保活进程由本次操作负责收尾。仍拿不到新画面、桌面重新锁定或实际权限不满足时，记录具体准入条件并保留待验收状态。

## 验收范围与收尾

- 普通 smoke 和受影响专项按项目合同选场景、时限和断言。安装包验收绑定完整版本、源码、包名、制品 SHA-256、签名和实际 helper。报告 checkout 启动故障时，绑定该 checkout 的源码和 dirty 内容，在来宾隔离副本运行报告的原命令。renderer 恢复、系统文件选择、升级和长时间观察各用项目对应场景。
- 保留 PID 归属明确的原生窗口图、实际用户操作、业务结果和适用的 AX／Trace。分别判定访问、登录、当前执行主体权限和验收状态。审计器退出为零时仍读实际状态和原件。复用证据时核对候选、所需场景和清理记录。
- 队列使用短期单次请求，将请求 ID、服务世代和新鲜回执绑定到当前目标。超时后查原请求的进程和终局，确认结果前暂停重复输入或启动。保留首错、原始 stdout／stderr、耗时和清理回执。关窗后继续确认自有 app、服务和子进程退出及私有数据清理，再进入下一例。清理仍不明时保留阻塞和现场。

## 持久恢复设施的验收

需要应对宿主或网络长期不可用时，优先复用获准的带外通道。若另行获准建设服务，优先来宾本地的受限服务和专用私有信箱，权限只覆盖所需操作。分别实测冷启动登录前应答、锁屏时允许的操作、无网时执行、超时回执及锁释放。只实测过诊断的服务记录为诊断可用。原生 GUI 能力要另用真实用例验收。
